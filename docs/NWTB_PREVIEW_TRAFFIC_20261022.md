# Office Driver Preview: traffic and arrivals

Baseline: `40875d08b705eae24b9bbfc5975458ff99593efc`.

Both Office editions' Driver View still opens the dedicated, read-only Office Route Screen. Its existing Leaflet map now installs `office-route-traffic.mjs`, reusing the same authenticated TomTom traffic layer as Live Drivers. Traffic colors appear above the saved road stroke and below stop pins. The overlay has its own on/off control; hiding it does not disable arrival estimates.

The arrival table shows the remaining saved stops and return destination, Central time, minutes from the estimate's calculation time and per-leg traffic delay. Clicking a row focuses its saved map pin. Planned routes explicitly show **IF DEPARTING NOW FROM [SAVED START]**. Active routes use only the existing driver's latest valid GPS fix. Completed stops are omitted from the ETA calculation; the return leg remains estimated until the driver explicitly confirms return. Stale/poor/missing GPS, paused/completed routes, missing coordinates and provider failures produce an unavailable state rather than a fabricated ETA.

The new Office-only `nwtb-office-map` action `route_preview_eta` reads canonical route/stops and location records. Client coordinates cannot override them. The server sends the saved order to TomTom with `computeBestOrder=false`, live traffic enabled and no route writes. It checks the saved state again after the provider responds and refuses estimates invalidated by stop completion, reassignment, pause, route completion or endpoint changes. Caches are bounded to 128 contexts and 30 seconds. The UI also checks the route revision and stop list, and clears old figures when traffic/GPS ages out. Route changes require REFRESH SAVED ROUTE.

Only a route-level service total is stored. The ETA allocation preserves that total using the route builder's pickup/delivery weighting and includes estimated service before subsequent arrivals. The table explains this estimate. TomTom's road choices can differ from the existing OSRM driver navigation; the stop order and saved road preview are retained. Stored route mileage, drive/service/return metrics are never replaced by these live estimates.

Traffic estimates refresh every 30 seconds while the preview is visible; traffic tiles retain their existing 60-second policy. Closing/replacing the modal, hiding the tab or changing the Office session aborts outstanding work and rejects late results. Driver login/token, GPS watches, route activation, release/hold and POD behavior are unchanged. No Driver session is started by the Office preview.

`20261022-trafficeta1` versions both Office shells' Dispatch/Driver Preview frames, both Dispatch builds, the route-admin/map modules and the dynamically imported ETA module. Production verification now includes `./` module dependencies. Automated tests cover the actual composed traffic layer and ETA table, planned/active/custom/return routes, service allocation, authorization, no writes, stale data, provider failure, asynchronous races, session separation, visibility, cleanup and all previous NWTB regressions. No test delivery or active route is created or altered.
